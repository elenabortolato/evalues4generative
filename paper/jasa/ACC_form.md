## Abstract

All data are generated by the code. The simulation studies and the multi-arm
multi-stage trial simulate their data; the trial uses the patient parameters of
simglucose, the open-source implementation of the UVA/Padova simulator. The
language-model audit uses replies generated by the code from the publicly
released Qwen2.5-1.5B-Instruct (8, 4 and 3 bits) and Qwen2.5-0.5B-Instruct
(4 bits) models: 1500 to 3000 replies per model and prompt, for four prompts,
stored in `data/llm_audit/replies.json`.

# Part 2: Code

## Abstract

The Python package `e4g` implements the Monte Carlo e-process, the hedged
wealth and the score learners: the Bayesian learning rule on the logistic loss
and on the simulation likelihood, predictive-first updates and a
Bayesian-bootstrap forest. The folder `experiments/` contains one script per
experiment, which writes its numbers to `results/` (JSON), its figures to
`figures/` and, for the language-model audit, the LaTeX of Tables 6 and 7. The
concurrent methods compared in the paper (Forré and Brenner; SLICE) are
reimplemented in the same scripts. The folder `tests/` checks, among other
things, that every bet has mean exactly one under the null.

## Instructions

Install the packages listed in Section 1 of `REPRODUCIBILITY.md` and run
`python -m pytest tests`. `REPRODUCIBILITY.md` then lists, for every table and
figure of the paper and of the supplement, the command that produces it, the
output file and the running time; all commands are run from the repository
root. The JSON files in `results/` hold the numbers reported in the paper, so
each table can be checked against them without re-running, and
`experiments/exp16_tables.py` prints Tables 6 and 7 from them. Every
replication is seeded. On a different processor, OpenBLAS can round matrix
inversions differently, which can move a few entries of Tables 6 and 7 within
Monte Carlo error; `REPRODUCIBILITY.md` documents this.
